# Требования к ImageAnalyzerS3

Цель проекта — разработать backend-сервис, который принимает фотографии, сохраняет их в облачном хранилище, ставит задачи на анализ в Kafka и возвращает результаты через API.

Анализ выполняет отдельный сервис, который система использует как внешнюю зависимость. В объём проекта входят интеграция с этим сервисом и обработка его результатов. Разработка алгоритмов анализа и обучение моделей находятся за рамками проекта.

Отмечай пункт, когда его критерий выполнения подтверждён.

## Проектирование

- [ ] Изучена предметная область и технологии, нужные для реализации. Определены роли HTTP/gRPC, Kafka и Kubernetes в системе.
- [ ] Спроектирована микросервисная архитектура. На схеме показаны границы сервисов, взаимодействие по HTTP/gRPC, передача задач через Kafka, облачное хранилище, СУБД и внешний анализатор.

## Функциональные требования

- [x] **Приём и сохранение фотографий.** Сервис сохраняет изображение в облачном хранилище и возвращает ID задачи после фиксации одной транзакции для записи задачи и события outbox. [Контракт `POST /api/analyze`](docs/architecture.md#post-apianalyze).
- [ ] **Асинхронная постановка задач.** Publisher читает outbox и публикует задачу в Kafka. Запрос на загрузку завершается без ожидания публикации и анализа.
- [ ] **Интеграция с анализатором.** Обработчик получает задачу из Kafka, передаёт фотографию внешнему сервису анализа и сохраняет результат в СУБД с привязкой к идентификатору фотографии.
- [ ] **Получение результата.** По идентификатору задачи API возвращает результат анализа. Для незавершённой обработки и неизвестного идентификатора предусмотрены документированные ответы.

Для каждой фотографии результат включает:

- [ ] Признак смазанного снимка.
- [ ] Количество лиц.
- [ ] Признак наличия дубликата.
- [ ] Признаки неудачного кадра, например закрытые глаза.

## Надёжность и эксплуатация

- [ ] **Хранение данных.** СУБД хранит данные о фотографиях и результаты анализа. Сохранённый результат доступен через API после перезапуска сервиса.
- [ ] **Обработка сбоев.** Определено и проверено поведение при недоступности анализатора и повторной доставке задачи из Kafka.
- [ ] **Фоновая сверка S3 с PostgreSQL.** После окна ожидания удаляются объекты, для которых подтверждено отсутствие задачи в БД. [Правила очистки](docs/architecture.md#очистка-объекта-в-s3-после-ошибки-бд).
- [ ] **Наблюдаемость.** По логам можно проследить обработку фотографии от загрузки до результата или ошибки. Метрики обработки доступны в системе мониторинга.
- [ ] **Документация API.** Описаны операции загрузки и получения результатов, форматы запросов и ответов, ошибки и примеры вызовов.
- [ ] **Контейнеризация.** Сервисы проекта собираются и запускаются в контейнерах.
- [ ] **Развёртывание.** Проект развёрнут в Kubernetes по инструкции запуска.

## Приёмка и сдача

- [ ] В развёрнутой системе пройден сквозной сценарий. Фотография загружается, сохраняется, уходит на анализ через Kafka, а API возвращает результат со всеми четырьмя характеристиками.
- [ ] Подготовлены исходный код, инструкция по запуску и краткое описание реализованной функциональности.
